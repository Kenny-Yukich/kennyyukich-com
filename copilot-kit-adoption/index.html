02

The adoption system

Make the first win real, then make it repeatable

I treated adoption as an operating rhythm rather than a launch event. Each phase had a behavior to create, evidence to inspect, and a decision about what deserved to scale.

P0 / Prepare

Fit seats to work

Map recurring tasks, select the cohort by task fit, settle governance questions, and publish the measurement rules before launch.

Exit: named cohort + honest baseline
P1 / Land it

Train on live work

Use the participant's document, email, meeting, or operational decision and coach one useful result before teaching breadth.

Exit: one usable result per person
P2 / Make it stick

Create peer pull

Identify champions from repeated behavior, run office hours, publish peer proof, and support dormant seats before reclaiming them.

Exit: named weekly workflows
P3 / Institutionalize

Engineer what lasts

Promote only repeated, governed work with shared value and a named owner into templates, flows, agents, or applications.

Exit: an evidence-backed backlog
Operating cadence Weekly prompt Biweekly office hours Monthly champion proof Quarterly capability review

What did not work

The lessons that changed the program

  • Training the tool instead of the taskFeature tours created recognition, not repeat behavior.
  • Choosing champions by enthusiasmPeer influence showed up in behavior, not launch-day excitement.
  • Reclaiming dormant seats too quicklyA fair support cycle had to come before reallocation.
